              topics, 54 Hz pairs, mono8, 1 kHz IMU are unchanged (counts OK: MIO07 4095/4095/76007, MIO13 20227/20227/375436,

              DynaVINS: 2037 poses but diverges (y runs away quadratically from ~12 s; ATE 144 m, rotation only ~1 deg) -> A2.

    -> src/savior/sota/config/monado/{vins_fusion/calibration.yaml, dynavins/calibration_stereo.yaml})
    Problem : the configs copied the Basalt continuous-time densities (acc_n 0.016, gyr_n 0.000282, acc_w 0.001, gyr_w 1e-4)
              into VINS's acc_n/gyr_n/acc_w/gyr_w. VINS-Fusion's own values are hand-inflated (EuRoC: 0.1 / 0.01 / 0.001 / 1e-4

              (src/savior/sota/config/warehouse/*, M3b) already define the rule for a new sensor: upstream EuRoC value x
              (dataset density / EuRoC density). The Monado configs did not apply that rule -> IMU 50-60x over-confident.
    Fix     : the warehouse rule, no free parameter: acc_n 0.1*0.016/2.0e-3 = 0.8; gyr_n 0.01*0.000282/1.6968e-4 = 0.01662;
              acc_w 0.001*0.001/3.0e-3 = 3.333e-4; gyr_w 1e-4*1e-4/1.9393e-5 = 5.156e-4. Identical for both baselines.
              Nothing else changed (cam*_kb.yaml unchanged: Basalt kb4 k1..k4 = camodocal KANNALA_BRANDT k2..k5 and
              body_T_cam = Basalt T_i_c = cam->IMU, both verified identical to the OpenVINS kalibr files; td 0 = dataset
              cam_time_offset_ns 0; g_norm 9.558 as OpenVINS; freq/output frame unchanged).
    Evidence (MIO07 only): debug runs off 0.0 / 1.0: VINS-Fusion 0.038 / 0.062 m, DynaVINS 0.072 / 0.090 m (OpenVINS 0.038 m).
